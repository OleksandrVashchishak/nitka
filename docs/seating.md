## 2. Модель даних

### 2.1 Чернетка (`draft`) — результат візарда

```
draft.tables  — формат і кількості: hasPresidium, presidiumSeats, format (round|long|mixed|p-shape|t-shape),
                roundTableCount/SeatsPerTable, longTableCount/SeatsPerTable,
                hasKidsTable, kidsTableCount, kidsTableShape
draft.guests  — groups: [{id, name}]
                assignments: { [guestKey]: groupId | "presidium" | "kids" | null }
                detachedKeys: [guestKey]     ← хто «від'єднаний» від свого ланцюжка
```

Групи (`assignments`) впливають на план **лише один раз**, коли план будується з нуля
(`autoSeat`). Далі вони дають тільки колір кружечка і фільтр «Групи».

### 2.2 План (`plan`) — що реально на карті

```
plan.tables[]  — {id, kind, shape?, label, x, y, rotation?, seats: [{id, guestKey|null}]}
plan.knownKeys — гості, яких план уже «бачив» (для автопосадки нових)
```

### 2.3 Ключ гостя (`guestKey`)

Один рядок у розсадці = **одне місце**:

| Хто | Ключ |
|---|---|
| Гість із БД | `guest.id` |
| Його «+1» / супутники з `notes` | `guestId:plus`, `guestId:plus:1`, … |
| Наречені (їх у БД немає) | `__couple__:1`, `__couple__:2` (віртуальні, завжди «Прийде») |

Наслідки:
- Гість зі статусом **«Не прийде» зникає** з розсадки повністю (і з місця теж).
- Запис типу «Колеги з офісу», «Друзі з університету (4 людини)», «Вікторія й Роман»
  займає **одне** місце. Розсадка не знає, що там кілька людей.
- `plusOne: true` без імені («Хрещені») — супутника в розсадці **немає**.

### 2.4 Ланцюжки (родини / пари)

`flattenSeatingGuests` збирає ланцюжок так:
1. Явна родина: `party:<id>` у `notes` (так створюються гості через «+1» у формі).
2. **Інакше — однакове останнє слово імені** («прізвище»), якщо в імені ≥2 слів.
3. Плюс супутники з `notes` / `plusOneName`.

Голова ланцюжка — перший дорослий. Дитина головою не буває. Якщо в ланцюжку самі діти,
ланцюжка немає.

⚠️ Правило «прізвища» склеює однофамільців, які не родичі (два різних «Петренко»), і не
склеює подружжя з різними формами прізвища (Білий / Біла).

### 2.5 Діти

- Дитина = `[child]` у `notes`; де сидить, видно з `need:` (`high_chair` / `with_parents` / `kids_table` / нічого).
- `childGoesToKidsTable` (з коду): на дитячий стіл іде дитина **без** `high_chair` **і без** `with_parents`.
- `high_chair`: дитина не займає місця — крісельце біля дорослого (`highChairHosts`), пересідає разом із ним.
  У попапі для `with_parents` пишеться «дорослий стіл».
- ⚠️ `.claude/rules/seating-wizard.md` каже протилежне: «`kids_table` / `with_parents` / без потреби → дитячий стіл».
  Правило й код розійшлися, треба вирішити, як правильно, і оновити одне з них.
- При завантаженні (`syncKidsAssignments`): дитина без групи → `kids`; якщо дитячого столу
  немає, `kids` знімається. Ручні групи не чіпає. Уже збережене `kids` для дитини з
  `with_parents` теж не чіпає («Тест Дитина» в сиді так і сидить за дитячим столом).

## 3. Флов користувача

### 3.1 Вхід на `/seating`

```
немає даних весілля      → «Спочатку збережи дату весілля…»
draft == null, гостей 0  → порожній стан «внесіть гостей» → /guests
draft == null, гості є   → порожній стан «N гостей чекають…» → [Розпочати розсадку] → візард
draft є                  → План (SeatingPlan)
```

### 3.2 Візард

1. **Столи**: президіум так/ні (+ кількість місць), формат, кількість столів і місць, дитячий стіл (кількість, форма; 8 місць фіксовано).
2. **Гості**: групи; кожному гостю група / президіум / дитячий стіл; «Від'єднати від …» у ⋮.
   Призначення голові підтягує весь ланцюжок (`applyLinkedAssign`), крім дітей за дитячим столом.
3. «Розсадити автоматично» → зберігає `draft` і будує план:
   наречені в центр президіуму → президіум → діти → групи по порядку → решта; кожен у
   **перший стіл, де є вільне місце**.

⚠️ **(з коду)** Коли `draft` уже є, з плану **немає кнопки повторно відкрити візард**.
Гілка `finishWizard(payload, true)` (перезбирає план) у `couple-seating-page.tsx` недосяжна.
Змінити формат або кількість столів можна лише руками («Додати стіл», модалка столу).

### 3.3 План — мобільний (< 768px)

Три вкладки. Після перезавантаження відкривається **«Список гостей»**.

**Список гостей**
- Рядок: номер, ім'я, іконка дитини, статус RSVP, сторона (аватар нареченої / нареченого / обоє).
  Кружечок: сірий з номером = сидить; пунктир = без місця; колір = група.
- Пошук і «Фільтри» (bottom sheet: Посадка / Групи / Гості / Столи; «Застосувати» / «Скинути»).
- Тап по рядку або ⋮ → bottom sheet гостя:
  - змінити статус («Можливо» / «Не прийде» / «Прийде») — пише в БД гостя;
  - «Залишити поки що без місця» (якщо сидить);
  - «Від'єднати від …» (якщо в ланцюжку);
- Перетягувати з цього списку на мобільному **не можна** (`draggable={!isMobile}`).

**Карта розсадки**
- Весь план вписаний в екран; pinch-zoom (1–4×) і пан двома пальцями.
- «Додати стіл», «Показати імена», внизу блок «Групи» (тап по чипу ховає колір групи; олівець → модалка груп).
- Тап по **зайнятому** місцю → попап: «Звільнити місце», «Поміняти місцями з …» (лише з сусідами зліва/справа за тим самим столом).
- Тап по **порожньому** місцю:
  - якщо є «обраний» гість **без місця** → сідає одразу, без питань;
  - інакше відкривається fullscreen «Посадити» (лише гості **без місця**).
- Перетягування пальцем кружечка з місця на місце / на стіл (поріг 8px). Перетягування столу (snap 24px), тап без руху по столу → модалка столу.

**Столи**
- «Додати стіл» (тип → модалка: кількість столів + місць на стіл).
- Список столів `заповнено/всього` → тап → модалка столу: Зробити круглим/довгим, Додати крісло, Очистити, Видалити, Повернути 30/60/90/180, Скасувати / Зберегти.

### 3.4 План — десктоп (відмінності)

Ліва панель зі списком і фільтрами + полотно. HTML5 drag&drop: гість зі списку або з місця
→ на місце або на стіл (стіл = перше вільне місце; повний стіл → тост). ⋮ у рядку →
плаваючий попап (без «Посадити за стіл», див. D1). Вікно конфлікту — та сама нижня шторка,
що й на мобільному (D2). Клік по рядку робить гостя «обраним»: наступний клік по порожньому
місцю його посадить.

### 3.5 Правила посадки (`seatFromPicker`, спільне для тапу, drag і модалки)

```
партнер = голова ланцюжка (для супутника) або ПЕРШИЙ член ланцюжка (для голови); від'єднаних ігноруємо
якщо партнера немає / він уже за цим столом / це дитячий стіл
      → садимо лише цього гостя
інакше якщо за столом є ще одне вільне місце
      → гість на обране місце, партнер на ПЕРШЕ вільне місце столу (не обов'язково поруч)
інакше → sheet-конфлікт:
      «Садимо X без Y» / «Не садимо їх за цей стіл» /
      «Садимо обох, але пересаджуємо когось іншого з цього стола в непосаджені» → вибір кого
```

Якщо обране місце зайняте, попередній гість **звільняється** (див. баг B3).

### 3.6 Нові гості після побудови плану

Новий гість (ключа немає в `knownKeys`): дитина сама сідає за дитячий стіл; **доросла людина
лишається без місця** (свідомо, щоб пару не розкидало). Гість, якого видалили або поставили
«Не прийде», сам звільняє місце.

Перевірено 2026-11-18 (створив через API трьох гостей і відкрив `/seating`):

- дорослий → без місця;
- дитина без `need:` → сама сіла за дитячий стіл;
- дитина з `need:with_parents` → **без місця**, хоча правило каже «дитячий стіл» (див. 2.5);
- усі троє одразу потрапляють у `knownKeys`, тож автоматично вже не сядуть ніколи.
  Підказки «з'явились нові гості без місця» немає (див. U7).

### 3.7 Збереження

- План: autosave через 500 мс після будь-якої зміни (`PUT /api/seating/plan`). Помилку
  **мовчки ковтає**, а індикатор «Авто-збереження» зелений завжди. **(з коду)**
- Також один PUT плану йде **одразу при відкритті сторінки**, без змін (видно в network).
- `detachedKeys` з плану пишуться в `draft` (`PUT /draft`).
- Групи з модалки (олівець) → `PUT /draft`, план не перебудовується.

**B13 ✅ Видалення столу без підтвердження**: усі, хто там сидів, мовчки стають без місця.

### Мобільний UX

**U1 ✅ Місця на карті 12×12 px на екрані** (план вписаний у 375px). Норма для тапу ~44px.
Промахуватися легко, з pinch-zoom краще, але за замовчуванням це основний спосіб взаємодії.
**U2 ✅ Імена на карті налазять одне на одне** між Столом 1 і Столом 2 («Марія Шевч…»,
«Сусідка Оксана» залазять на сусідній стіл). Над і під планом багато порожнього місця.
**U3 ✅ Попап місця на мобільному** має лише «Звільнити місце» (+ обмін із сусідами).
Немає «Пересадити», статусу, від'єднання. Усе це тільки в sheet списку.
**U4 ✅ Модалка «Посадити» не каже, який це стіл і місце.**
**U5 ✅ Після перезавантаження завжди вкладка «Список гостей»**, навіть якщо працював на карті.

### Десктоп (ретест 2026-11-18, 1440×900)

Перевірено тим самим акаунтом. Drag-and-drop відтворено справжніми `DragEvent`, бо панель
браузера була надто вузька для скриншотів.

**Те саме, що на мобільному:**

| Баг | Що зробив | Що вийшло |
|---|---|---|
| B1 | Клік по Олені на карті → «Звільнити місце» | Звільнились Олена й Тарас, без питання |
| B3 | Drag Сергія на місце Олени | Олена мовчки без місця, Тарас лишився сам |
| B4 | Клік по рядку непосадженої Олени → клік по порожньому місцю | Сіла одразу, без модалки й без підказки «обрано» |
| B5 | ⋮ → «Від'єднати від Тараса» | Звільнились обоє |
| B6 | Модалка столу: «Додати крісло» (11) → клік по кріслу | Знову 10 |
| B7 | Пошук «Сергій» → клік по порожньому місцю | У «Посадити» — «Гостей не знайдено», хоча Тарас без місця |
| B10, U4 | Модалка «Посадити» | Кружечки «О»/«Т» — перші літери імен; не видно, який стіл і місце |
| B13 | «Видалити стіл» | Без підтвердження й undo, є лише тост «Стіл видалено» |

**Працює:**

- Клік по порожньому місцю відкриває «Посадити». Обрав Олену, і Тарас сів на сусіднє місце.
- Drag місця на порожнє місце іншого столу — гість пересідає.
- Drag рядка зі списку на назву столу — сідає на перше вільне місце. Пара переїжджає
  разом: Тарас пішов зі Столу 3 за Оленою.
- Drop на повний стіл показує тост «Немає вільних місць за цим столом».
- Вікно конфлікту з'являється, коли пару кидають на стіл з одним вільним місцем.
  «Садимо Андрія без Наталі» садить його окремо, а в списку вони лишаються пов'язаними.
- Лічильник «N / M розсаджено» видно (на мобільному прихований, U7).

**Тільки на десктопі:**

- **D1 ✅ Немає способу пересадити гостя, який уже сидить, крім drag.** Меню ⋮ у списку для
  такого гостя: статус, «Залишити поки що без місця», «Від'єднати». Пункту «Посадити за
  інший стіл» немає, хоча на мобільному він є (там він не працює, B2).
- **D2 ✅ Вікно конфлікту — мобільна шторка на десктопі.** `.seat-plan-sheet` займає всю
  ширину внизу екрана (1425×213 px), далеко від столу, на який кинули гостя.
- **D3 ✅ Імена на карті налазять одне на одне й на сусідній стіл.** Між Столом 1 і Столом 2
  4 пари накладаються: Катерина Бондар ↔ Андрій Петренко, Олег Савчук ↔ Тест Основний,
  Сусідка Оксана ↔ Марія Шевченко, Тест Другий ↔ Колеги з офісу. Ще 11 з 19 імен обрізані
  трикрапкою. Місця 26×26 px — для миші нормально.
- **D4 🔎 Перетягування столів не перевірено.** Синтетичні pointer-події стіл не рухають
  (схоже, через `setPointerCapture`). Перевірити мишею вручну. За кодом перевірки
  «стіл на стіл» немає.

### Розбіжність правил і коду

- `with_parents` → дитячий стіл (правило) чи дорослий (код), див. 2.5.
- Правило: «без “вибрав гостя → клік по місцю”». Код: клік по порожньому місцю садить
  обраного гостя (і на десктопі, і на мобільному). Звідси B4.
