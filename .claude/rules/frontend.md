# Frontend (apps/web)

## Незмінні пріоритети

- **Мінімальний diff** — лише те, що треба для задачі. Без реформату, перейменувань і перепису стороннього коду.
- **Не міняти архітектуру** без потреби — не переносити компоненти, не перейменовувати папки, не міняти імпорти / структуру стилів, якщо задача цього прямо не вимагає.
- **Reuse first** — перед новим шукати наявні компоненти, стилі, утиліти, хуки, responsive-патерни.
- **Існуючий UI = джерело правди** — spacing, typography, breakpoints, naming, поведінка як у схожих місцях проєкту.
- **Не вигадувати дизайн/UX** — якщо дизайн/вимоги не кажуть «як», брати найближчий патерн або мінімальне рішення. Без зайвих hover/animation/loading/fallback «для краси».

## UI kit first (`components/ui/`)

Перед кнопкою, інпутом чи іншим примітивом — **спочатку** дивись `apps/web/src/components/ui/`:

1. Є компонент з потрібними props / size / tone / variant → **використовуй його**. Не клонуй розмітку й стилі «під цю сторінку».
2. Майже підходить → **розшир props** існуючого компонента, не плоди `MyButton` / дубль CSS.
3. Новий файл у `ui/` — лише якщо аналога немає і примітив реально шариться (≥2 місця) або явно просять у кіт.
4. Окремі іконки / дрібні атоми поруч (`icon-*.tsx`, `ui-loader` тощо) — теж спочатку grep / reuse, потім нове.

Приклади вже в кіті: `Button` (`size`, `tone`, `loading`, `href`), `TextInput` (`size`, `shape`, `label`, `hint`, `endAdornment`).

## Новий frontend code

- Нові стилі → BEM + SCSS: `.block`, `.block__elem`, `.block--mod` (`&__` / `&--`)
- Без CSS Modules і без Tailwind у новому коді (якщо явно не просять інакше)
- Стилі → `apps/web/src/styles/` по доменах (`ui/`, `cabinet/`, `landing/`, `website/`, `wedding-site/`…). Компонентний SCSS поруч — лише якщо зона вже так живе
- Доменні block-names (`wsite-`, `ws-`, `we-`…) або осмислений новий — без `btn2` / `cardNew`
- Токени зони з `_variables.scss` замість нових hardcoded значень (колір, шрифт, spacing, радіуси)
- Легасі flat SCSS у `styles/` (`cabinet/cabinet.scss`, `globals.scss`, `auth/login.scss`…) **не роздувати** новими фічами, якщо явно не просять
- Розширення стилів — **лише `.scss`** (не плодити нові `.css`)
- Responsive — `@media` **всередині** відповідного класу; не створювати нову систему breakpoint-ів — брати існуючу зони:

```scss
.card {
  padding: 40px;

  @media (max-width: 768px) {
    padding: 20px;
  }
}
```

- `"use client"` — лише коли реально потрібні хуки / браузерні API
- Витягувати компонент — коли шариться або файл уже жирний; не абстрагувати «на майбутнє»

## Код і залежності

- Існуючий компонент/стилі **не рефакторити** на BEM «по дорозі» — лише за прямим запитом
- Перед helper/hook/utility — перевірити аналоги в проєкті; не дублювати
- Нові npm-пакети — лише якщо задачу не закрити наявним стеком
